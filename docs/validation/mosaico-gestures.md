# Mosaico 手势固件：首次烧录与验收

本功能在设备本地运行：左挥下一页、右挥上一页；时钟中首次挥手只恢复原页面；👌 OK 稳定停留约 500 ms 进入时钟。一轮操作最多触发一次，需要手离开后再操作。触摸和 AI 键继续可用。

这是供实机验收的实现。软件测试与固件构建不能证明相机成像、方向、识别率、功耗或长期稳定性；这些仍需在目标设备验证。

## 首次安装的分区变化

两款模型与固件共同超过原有 4 MiB 应用槽。新布局使用 7 MiB 双 OTA 槽，模型内嵌，支持代码与模型一起更新和回滚。

| 分区 | 原布局 | 新布局 |
| --- | --- | --- |
| NVS | `0x9000` / `0x6000` | 保持 |
| PHY | `0xf000` / `0x1000` | 保持 |
| ota_0 | `0x10000` / `0x400000` | `0x10000` / `0x700000` |
| otadata | `0x810000` / `0x2000` | 保持 |
| ota_1 | `0x410000` / `0x400000` | `0x820000` / `0x700000` |

第二槽结束于 `0xf20000`，在 16 MiB Flash 内；`0x710000` 到 `0x810000` 的空隙保留现有 otadata 地址。Folder Push 限额同步为 7 MiB + 512 字节，目标注册表和 Bridge 下载上限同步更新。

**旧 4 MiB 分区不能通过应用 OTA 安装本镜像。首次必须通过有线写入新分区表、应用和初始 OTA 元数据。**设备原有容量检查会拒绝超大镜像；不要绕过检查。现有已安装 Bridge 若仍使用 4 MiB 下载上限，也不能用于传送新镜像。

优先使用构建生成的分段烧录参数，保持 NVS 扇区不被覆盖。合并的 full 镜像包含分区间填充，整段写入可能覆盖 NVS，不能用它声称保留配对/设置。本次实现不自动烧录或擦除任何设备。

## 从源码准备与烧录

在仓库根目录：

```sh
eim --version
eim list
eim run "idf.py -C firmware/targets/esp_mosaico build" v6.1
```

确认生成配置包含 `CONFIG_MOSAICO_GESTURE_INPUT=y`、`CONFIG_CAMERA_OV3640=y`、640×480 UYVY 模式，`CONFIG_ESP_DESKTOP_BUDDY_FOLDER_PUSH_MAX_TRANSFER_BYTES=7340544`，以及 `QF-Mosaico-` 广播前缀。旧生成配置可能保留不同前缀，不能只检查 defaults。构建产物中的 `flash_args` 是本次镜像的地址来源。

设备接入左侧 OV3640 CameraBoard。先在设备设置中关闭手势，或断电安装相机板；使用真实串口替换下述 `PORT`。手动进入下载模式后，在 **build 目录**运行：

```sh
python -m esptool --chip esp32s31 --port PORT --baud 460800 \
  --before no-reset --after no-reset --no-stub write-flash @flash_args
```

该命令需要已启用的 ESP-IDF v6.1 Python 环境。等待逐段校验成功后手动重启。它写入 bootloader、分区表、ota_0 和 `ota_data_initial.bin`；不包含 NVS，也不执行 `erase-flash`。原有第二槽内容被新的大应用覆盖，首次迁移后不能依赖旧第二槽自动回滚。

如需恢复旧版，先准备旧版的完整、匹配的分段文件（旧分区表、旧应用、bootloader、初始 OTA 元数据），再次进入下载模式写入它们。不要单独写回旧分区表，也不要省略重置 OTA 元数据；旧配对和显示设置所在 NVS 地址未变。未来在新布局内进行正常 A/B OTA 时，无需重复迁移分区。

## 启用与操作

1. 长按现有显示设置入口，选择 `HAND GESTURES / ON`，点击 `SAVE`。默认关闭；取消不会启用摄像头。
2. 等待 `CAMERA STARTING` 消失，先把手移出画面至少约半秒，再开始动作。
3. 正常页左右挥动；一次只翻一页。屏保中第一次挥动只恢复原页。
4. 正常页做 👌 OK 并短暂停留；进度条完成才进入时钟。进入后先移开手，下一轮挥手再唤醒。
5. 设置、配对确认和 OTA 期间不接受手势。关闭并保存后释放采集和模型资源。

`CHECK LEFT CAMERA` 表示采集未能启动或连续失败。检查左槽相机，关闭并保存，再开启并保存可重试。`LOW MEMORY` 表示资源预检查未通过；`RESTART DEVICE` 表示驱动资源未能安全释放，需要重启后再试。

摄像头占用 USB Serial/JTAG 的 GPIO33；运行期间使用 UART 获取诊断。日志只报告动作、周期时间、内存和栈余量，不输出图像或用户数据。屏保时摄像头仍工作，因此本功能不是深睡眠唤醒，也未验证续航收益。

## 实机验收顺序

- 首先确认原有触摸、AI 键、BLE、显示旋转和 OTA 确认界面工作正常。
- 检查相机能连续采集，记录 `gesture_input` 周期与内存日志；缺相机时面板应继续工作。
- 在每个屏幕朝向检查左右语义。默认相机安装修正为 180°、镜像开启；若方向或手形识别不正确，使用 `menuconfig → Camera gestures` 校准后重建，不能把主机坐标转换测试当作硬件方向验证。
- 分别在三个用量页进入时钟，再挥手，确认回到原页且不继续翻页。保持 OK、自然松手和单帧漏检都不应反复切换。
- 测试设置/配对/OTA 期间持续挥手，退出后不能回放旧动作；随后移开手再做新动作应恢复。
- 记录实际距离、照明和方向；每朝向每方向至少 20 次，并在打字、拿杯等场景观察至少 30 分钟误触。连续运行及反复启停，检查内存是否稳定。
- 同亮度、同 BLE 负载比较手势关闭、正常页启用、屏保启用时的电流和界面响应。尚未测得的数据不得标为通过。

识别距离、方向标定、模型延迟、功耗、实际摄像头热插拔和 A/B 回滚效果均为硬件验收项；初版只提供关闭/开启重试，不承诺热插拔自动恢复。

## 本次软件验证

- ESP-IDF v6.1：手势开启/关闭固件均构建成功；Mosaico logic 和共享 panel_state 测试镜像构建成功；受共享屏保接口影响的 AMOLED 2.16 固件构建成功。
- 主机实际运行 31 个手势/屏保 Unity 测试，ASan/UBSan 通过；测试镜像未在 MCU 上运行。
- Bridge：620 项测试通过，7 项跳过，包含新 7 MiB 发布清单容量和第三方许可检查。
- 未进行实机烧录。ESP-DL 内部模型分配包含断言；预检查不能替代内存压力与启停实测。
