# Mosaico 手势固件：安装与验收

本功能在设备本地运行：左挥或上挥上一页、右挥或下挥下一页；时钟中首次挥手只恢复原页面；👌 OK 稳定停留约 500 ms 进入时钟。一轮操作最多触发一次，需要手离开后再操作。触摸和 AI 键继续可用。

这是供实机验收的实现。软件测试与固件构建不能证明相机成像、方向、识别率、功耗或长期稳定性；这些仍需在目标设备验证。

## 当前分区与构建

16 MiB Flash 使用两个 7 MiB 应用槽，模型与代码共同更新。NVS 位于 `0x9000`，ota_0 位于 `0x10000`，otadata 位于 `0x810000`，ota_1 位于 `0x820000`。Folder Push 限额为 7 MiB + 512 字节，目标注册表和 Bridge 下载上限同步匹配。

在仓库根目录运行：

```sh
eim --version
eim list
eim run "idf.py -C firmware/targets/esp_mosaico build" v6.1
```

确认日志含 `Project build complete`，并检查生成配置启用 CLIB 分配器、OV3640 与 SC101IOT。SC101IOT 使用完整 1280×720 UYVY，驱动标称 15 fps；OV3640 使用 640×480 UYVY。

## 有线烧录注意事项

相机板安装在左槽，安装前断电。在已授权的有线烧录中，按住 BOOT 再开机进入 ROM 下载模式。Mosaico 实测整段擦写大应用可能断连；不要直接使用 `idf.py flash` 或将未拆分的大应用交给 `@flash_args`。

将应用按 1 MiB 拆分，地址从目标应用槽起点逐段递增，使用 ESP-IDF v6.1 环境中的 esptool，以 `--chip esp32s31 --no-stub`、460800 波特率、DIO/80 MHz/16 MB 参数写入，并指定 `--after no-reset`。烧录前校验分段拼接内容与构建应用一致，烧录后确认每段设备哈希校验成功，再通过 POWER 关机重启。

仅更新当前应用时，不写入 NVS、分区表或初始 OTA 元数据。需要完整安装时，使用构建产物匹配的 bootloader、分区表及初始化数据；应用仍分段写入。不要通过整片擦除或包含填充区域的合并镜像声称保留配对与设置。

## 启用与操作

1. 长按现有显示设置入口，打开 `CAMERA` 开关并点击 `SAVE`。默认关闭；`CANCEL` 不会启用摄像头。
2. 顶栏摄像头标识变为亮色后，先把手移出画面至少约半秒，再开始动作。
3. 正常页上下左右挥动；上/左为上一页，下/右为下一页，一次只翻一页。屏保中第一次挥动只恢复原页。
4. 正常页做 👌 OK 并短暂停留；进度条完成才进入时钟。进入后先移开手，下一轮挥手再唤醒。
5. 设置、配对确认和 OTA 期间不接受手势，标识转暗。关闭 `CAMERA` 开关并保存后释放采集和模型资源，顶栏标识消失。

顶栏标识带斜杠表示采集失败：相机未能启动或连续采集失败、资源预检查未通过，或驱动资源未能安全释放。检查左槽相机后，把 `CAMERA` 关闭并保存、再打开并保存可重试；仍带斜杠时重启设备。具体原因见 UART0 日志。

摄像头占用左侧排针上的 USB Serial/JTAG（GPIO33/34）。Type-C 口是 USB OTG，只在 ROM 下载模式下枚举，与摄像头无关；应用日志只从 UART0 输出（右侧排针 H1 的 15 脚 TX0 / GPIO58，或底板背面调试焊盘 TX，115200）。采集失败时每 5 秒打印一次 `capture unavailable: <步骤> (code N)`。板上没有 RST 键：复位用 POWER 键关机再开机，下载模式为关机后按住 BOOT 再开机。日志只报告动作、周期时间、内存和栈余量，不输出图像或用户数据。屏保时摄像头仍工作，因此本功能不是深睡眠唤醒，也未验证续航收益。

## 实机验收顺序

- 首先确认原有触摸、AI 键、BLE、显示旋转和 OTA 确认界面工作正常。
- 确认 `CAMERA` 开关保存后重启仍保持，切换开关会启用 `SAVE`、`CANCEL` 会恢复；保存为打开时顶栏标识出现，采集中为亮色，设置页、配对或 OTA 期间为暗色，失败时带斜杠；关闭并保存后标识消失。
- 检查相机能连续采集，记录 `gesture_input` 周期与内存日志；缺相机时面板应继续工作。
- 在每个屏幕朝向检查左右语义。默认先水平镜像再顺时针旋转 90°，与官方参考实现的逆时针 90° 正立画面一致；若方向或手形识别不正确，使用 `menuconfig → Camera gestures` 校准后重建，不能把主机坐标转换测试当作硬件方向验证。
- 分别在三个用量页进入时钟，再挥手，确认回到原页且不继续翻页。保持 OK、自然松手和单帧漏检都不应反复切换。
- 测试设置/配对/OTA 期间持续挥手，退出后不能回放旧动作；随后移开手再做新动作应恢复。
- 记录实际距离、照明和方向；每朝向每方向至少 20 次，并在打字、拿杯等场景观察至少 30 分钟误触。连续运行及反复启停，检查内存是否稳定。
- 同亮度、同 BLE 负载比较手势关闭、正常页启用、屏保启用时的电流和界面响应。尚未测得的数据不得标为通过。

识别距离、方向标定、模型延迟、功耗、实际摄像头热插拔和 A/B 回滚效果均为硬件验收项；初版只提供关闭/开启重试，不承诺热插拔自动恢复。

## 初始实现的软件验证记录

- ESP-IDF v6.1：手势开启/关闭固件均构建成功；Mosaico logic 和共享 panel_state 测试镜像构建成功；受共享屏保接口影响的 AMOLED 2.16 固件构建成功。
- 手势轨迹与屏保 Unity 测试曾在主机实际运行并通过 ASan/UBSan。之后新增的漏检、低置信度、慢帧与位置跳变用例仅随 logic 测试镜像编译，尚未在主机或 MCU 上运行；测试镜像未在 MCU 上运行。
- `CAMERA` 开关与顶栏标识只经过固件构建，布局与触控需实机确认。
- Bridge 全部测试通过，包含新 7 MiB 发布清单容量和第三方许可检查。
- 初始验证时未进行实机烧录；后续烧录与设备验证见下文。ESP-DL 内部模型分配包含断言，预检查不能替代内存压力与启停实测。

## 时钟黑屏排查（2026-09-23）

故障固件使用 LVGL 内置 64 KiB 内存池，未启用扩容。原始 UART 日志中的 ELF 哈希与排查用 ELF 匹配；进入时钟后，`swdraw` 的看门狗现场持续停在 `lv_draw_unit_draw_letter` 的 `LV_ASSERT_MALLOC(draw_buf)`。反汇编确认该地址为自跳转指令，前置分支仅在字形缓冲分配返回 NULL 时进入。因此，已确认直接故障为字形缓冲分配失败后断言死循环；现有日志不能区分内存池总余量不足与碎片化，也没有 main 分支的运行时内存池余量对照。

Mosaico 默认配置改为 `CONFIG_LV_USE_CLIB_MALLOC=y`，使界面对象和字形缓冲使用 ESP-IDF 标准堆。已有工作目录还需在生成的 `sdkconfig` 中关闭 `CONFIG_LV_USE_BUILTIN_MALLOC` 并启用 CLIB，重新构建后检查 `build/config/sdkconfig.h`。标准堆是否使用 PSRAM 由 ESP-IDF 的分配策略决定，不能将 CLIB 等同于强制 PSRAM 分配。

本轮 ESP-IDF v6.1 构建完成；生成配置启用 CLIB 和调试预览，最终 ELF 的 lv_malloc_core 直接跳转到标准 malloc。通过 UART0 被动读取的修复前设备日志仍停在同一断言地址。修复镜像已按 1 MiB 分段写入应用区，六段均通过设备哈希校验；未写入 NVS、分区表或 OTA 元数据。重启日志的 ELF 哈希与修复产物一致，摄像头和 BLE 均恢复运行。用户确认通过 OK 进入时钟后显示正常；后续 UART 采集日志持续输出，未再出现看门狗报警。日志另捕获到 SwipeLeft/Next 与 SwipeRight/Previous 各一次；这只能证明两个方向均已触发，不能代替触发率验收。

后续压力验收：保持调试预览开启，反复通过 OK 进入时钟并唤醒，覆盖分钟切换、触摸、BLE 和摄像头启停；确认画面正常、无 `swdraw` 看门狗，且现有 `internal_free`、`psram_free` 日志无持续下降。CLIB 后端不提供有效的 `lv_mem_monitor` 统计，应使用 ESP-IDF 堆统计。左右挥手的触发率仍待单独验证。

## 近距离取景调整

SC101IOT 使用完整 1280×720 画面，避免 VGA 模式的中心裁切；等比例缩为 320×180 RGB888，旋转后将实际尺寸传给模型和预览。OV3640 保持 640×480 采集、320×240 RGB888。手势阈值保持不变，以便单独验证取景范围变化。

本版应用与 logic 测试镜像均已通过 ESP-IDF v6.1 构建，新增图像比例、旋转、镜像和边缘保留用例仅完成编译，尚未运行。应用已按六段写入设备，全部通过设备哈希校验；未写入 NVS、分区表或 OTA 元数据。重启日志确认运行镜像与产物匹配，并成功采集 1280×720 UYVY；观察窗口内无看门狗或采集失败，记录到一次右挥翻页。稳定采样的平均处理周期约 105～123 ms，PSRAM 空闲约 4.39 MB。用户反馈近距离取景有所改善，但旋转后的竖幅横向空间不足；具体距离、OK 识别及左右挥手触发率尚未验收。检查启动日志包含 `camera UYVY 1280x720`，预览应包含更完整的场景且手形无拉伸；分别在约 40、30、25 cm 检查完整入镜、OK 进入时钟与左右挥手。记录实际识别率、平均周期、帧超时和内存余量，确认反复关闭/开启 CAMERA 与时钟切换正常。25～30 cm 是测试目标，不是已验证的识别距离。

## 空中挥手的页面方向

空中手势按导航项顺序选择页面：右挥或下挥为下一页，左挥或上挥为上一页，末尾按现有页面顺序循环。触摸滑动语义保持不变；时钟中首次挥手仍只唤醒。前述日志中的 SwipeRight/Previous 等记录属于调整前版本，不作为当前映射的验收证据。

方向调整后的应用与 logic 测试镜像均通过 ESP-IDF v6.1 构建；路由测试尚未运行，方向修正已随四向手势应用烧录，方向一致性待实机确认。

## 上下挥手

上下挥手与左右挥手共用单手置信度、150～900 ms 动作窗口、至少三帧、25% 主轴净位移和释放确认。斜向轨迹及往返抖动不应翻页；时钟中任一方向首次挥动只恢复原页。实机需分别验证上挥上一页、下挥下一页，以及一次动作不会重复翻页；新增四向逻辑尚未实机验收。

四向手势应用和 logic 测试镜像均通过 ESP-IDF v6.1 构建；扩展后的轨迹、斜向/抖动拒绝及动作路由测试尚未运行。应用已按六段写入设备，全部通过设备哈希校验；仅更新应用分区，未写入 NVS、分区表或 OTA 元数据。烧录结束后设备停留在下载模式，后续日志及用户反馈确认：手离开镜头后，上挥可唤醒时钟；其余方向和连续操作的完整验收仍待完成。

## 相机图标预览开关

预览默认隐藏，点击顶部相机图标切换显示；隐藏时跳过预览绘制，手势识别继续运行。应用通过 ESP-IDF v6.1 构建，已按六段烧录并全部通过设备哈希校验。仅更新应用分区，重启后已采集到分阶段性能日志，图标点击行为仍待用户确认。本版本包含采集转换、检测、分类和预览反馈的分阶段耗时统计。

预览交互验收需检查：启动隐藏、点击图标开关、图像比例及手部定位框、无调试文字；进入时钟或受保护页面后隐藏，恢复识别并返回普通页面后恢复本次选择。隐藏期间应跳过预览显示锁和绘制；实际锁竞争与帧率变化仍需测量，不能以构建结果代替性能验收。

## 性能基线与后续优化（2026-09-23）

预览关闭且未执行 OK 分类的三个连续约 10 秒窗口中，每窗口处理 80 帧，约 8 fps。平均采集与转换耗时 18.6 ms，手掌检测（含前后处理）86.8 ms，反馈约 0.006 ms，循环另有固定 20 ms 等待，总帧间隔约 125 ms。`mean_cycle_ms` 不含反馈及固定等待，不能直接取倒数作为识别帧率。该窗口不代表正常页检测到手后执行 OK 分类的完整负载。

[官方手掌检测基准](https://github.com/espressif/esp-dl/tree/master/models/hand_detect)给出同模型 S3 合计 132.8 ms、P4 合计 50.9 ms，未列 S31。[官方 S31 案例](https://esp32-s31.espressif.com/en/official-projects/6)中同系列 ESPDet-Pico 猫检测合计 94.9 ms，仅用于量级参考，不能视为相同模型的直接对比。当前 CPU 为 320 MHz，PSRAM 为 250 MHz。

后续按以下顺序评估，尚未实现，收益不得作为已验证结果：

1. 缩短固定 20 ms 等待，并检查 BLE、显示、看门狗和任务公平性。其他耗时不变时，理论上可接近 9.5 fps。
2. 将采集等待与图像转换继续拆分计时，再对照官方相机实现评估硬件缩放、旋转及转换。保留完整传感器视野，不通过中心裁切换取速度。
3. 测量正常页有手时的 OK 分类成本；评估移动时优先跟踪、稳定后再分类。时钟中已跳过 OK 分类，不能重复计算这项收益。
4. 若上述收益不足，再评估更轻模型或检测与轻量跟踪交替运行；验证快速运动、遮挡、多手及重新捕获，避免累计漂移。
5. 保留至少三帧确认，结合实际帧率评估 150 ms 最短动作时间、位移及位置跳变阈值。分别测量左右与上下挥手的成功率、误触率及唤醒延迟。

近距离优化需区分光学视野与识别条件：当前已使用 SC101IOT 完整画面；软件缩小预览不能扩大视角。可评估较小挥手幅度及大手掌框的过滤阈值，部分手掌入镜的识别可靠性需实测。预览开关的性能对比应采用相同手势、页面与照明条件。
