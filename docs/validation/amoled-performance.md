# AMOLED 2.16 内存与显示基准

以下为指定历史基线上的实测数据，用于解释设计约束和安排复测，不代表当前 ESP-IDF 6.1 固件的性能。最新功能与 OTA 验收见[验证入口](../verification.md)。

## BLE 短负载基准：2026-08-06

短负载探针基线；每轮发送 2,880 B 已知负载，编码为 3,887 B JSON 行，以设备解析完整行后的预期拒绝 ACK 作为完成信号。每种策略完成 5/5 行；数字只描述这组短负载往返，不代表完整固件传输或当前协议。

| 设备 | 写入策略 / 有效分片 | 中位吞吐 | 最差吞吐 |
| --- | --- | ---: | ---: |
| AMOLED 2.16 | 有响应 / 180 B | 0.868 KiB/s | 0.837 KiB/s |
| AMOLED 2.16 | 无响应 / 253 B | 7.836 KiB/s | 6.695 KiB/s |
| M5StickS3 | 有响应 / 180 B | 1.020 KiB/s | 0.977 KiB/s |
| M5StickS3 | 无响应 / 253 B | 9.378 KiB/s | 7.815 KiB/s |

同日另一次 M5 OTA 基线在 MTU 517、512 B 分片下测得中位 9.371 KiB/s、最差 5.222 KiB/s，5/5 行完成。样本量不足以证明长期可靠性，增大 MTU 也未在该组数据中证明吞吐提升。

## PSRAM 帧缓冲实验边界

- ESP-IDF v6.0.1：双帧 PSRAM 分配成功，内部空闲 106,607 B、最大连续块 65,536 B；实机出现白块、蓝线、触摸无响应及 `ESP_ERR_INVALID_STATE`。该组合未通过显示验收。
- ESP-IDF v6.0.2：实验未接通 BSP 的 `psram_dma_direct` 开关，未完成实测。

这些实验不能推出 ESP32-S3 不支持 PSRAM DMA，或当前 SDK 下所有方案均不可行。乐鑫说明直接 DMA 需使用相应标志，且与 MSPI 共享带宽；超过可用带宽可能丢失数据。旧实验中的带宽竞争是待进一步隔离的解释，不能将单次失败当成永久硬件限制。见[官方 SPI 文档](https://docs.espressif.com/projects/esp-idf/en/v6.1/esp32s3/api-reference/peripherals/spi_master.html#transactions-with-data-on-psram)。

480 × 480 RGB565 在 40 MHz 四线 QSPI 上的纯像素传输下界为 23.04 ms；不含绘制、命令、间隔和等待，不能作为实测刷新时间。

## 复测要求

结合[固件构建说明](../../firmware/README.md)显式选择项目 SDK 版本，并核对实际生成配置。记录提交、镜像摘要、UI 场景、缓冲配置、实际 MTU、刷新耗时样本，以及 BLE/OTA 负载下的内部空闲、历史最低值和最大连续块。烧录测试固件前确认设备并安排恢复生产配置。

比较显示方案应使用相同 SDK、UI 和测试条件。BLE 测量需单独统计纯传输区间；包含人工确认的 OTA 全程时间只适合描述操作耗时。功耗评估应测量整板电流与各工作状态持续时间；屏保显示与 SoC 休眠是不同状态，不能从轮询周期推算续航。
