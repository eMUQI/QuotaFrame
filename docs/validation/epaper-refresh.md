# ePaper 3.97 局刷验证参考

设备：ESP32-S3-ePaper-3.97，800 × 480，ESP-IDF v6.1。以下显示实验执行于 2026-09-12 至 15；原始记录未提供可完整重建的源码与配置快照，因此这些数据仅作为测试方法与耗时参考。最新连接、用量与 OTA 验收见[验证入口](../verification.md)。

## 已确认的关键行为

- 固定窗口 T 测试的图案位置已由用户照片确认。修正 RAM 同步后，“区域 1 → 空白 → 仅区域 2”序列经用户确认，已擦除图案不会在该序列中重新出现。
- 实际设置页选项的局刷与擦除已获用户操作确认；诊断 W 的横屏、跨行及竖屏操作有执行日志，不扩大为全部方向和长期光学验收。
- `g` 实验先显示四灰阶背景，再仅在黑白窗口更新 `12 → 空白 → 34 → 空白 → 12`，用户确认显示正常。该结果不证明灰色像素本身可以局刷，也不覆盖窗口重叠灰色区域。

原始驱动基于 Waveshare 提交 `9b12d40731a80213b927ee8a421cae4082952819`。窗口坐标和刷新后双 RAM 同步的维护说明见[驱动来源](../../firmware/targets/waveshare_epaper_397/main/vendor/UPSTREAM.md)，可重复操作见[局刷 demo](../../tools/ws397/PARTIAL_DEMOS.md)。固定多窗口诊断绕过上层旋转和帧差分，可用于区分窗口寻址与 UI 问题。

## 刷新耗时

| 测试条件 | 模式 | 记录耗时 |
| --- | --- | ---: |
| T：64 × 32 原生窗口、256 B 已知图案 | 单色局刷，三步 | 656 / 655 / 655 ms |
| W：设置选项、跨行及竖屏选项 | 单色局刷 | 657–674 ms |
| W：方向切换重建基准 | 单色全刷 | 2600–2601 ms |
| Home：正常与耗尽互换 | 单色局刷 | 665 ms |
| Home：在线与离线互换 | 单色局刷 | 681 ms |
| Home：测试数据恢复实时页面 | 单色局刷 | 701 ms |
| `g`：隔离窗口 256 × 128、4096 B | 五次单色局刷 | 630–631 ms |
| `g`：四灰背景基准 | 灰阶全刷 | 3207 ms |
| Clock：分钟、温度及湿度测试序列 | 单色局刷，一至多个窗口 | 708 / 1339 / 1339 / 1971 ms |
| Clock：灰阶基准 | 全刷及准备 | 3222 ms |

时钟多字段更新分多个窗口避开灰色分隔线，不能把多窗口总时间当成一次窗口传输。Home 和 Clock 的帧缓冲检查证明生成像素及执行模式；Clock 的灰色保持、擦除、跨午夜和各方向显示仍需专项光学确认。

## 运行与后续边界

当时 Home、Settings 和 Clock 的全刷间隔改为 20 次局刷，超过原记录引用的厂商“5 次局刷后全刷”建议。仍需观察多天残影、不同温度与方向；不能仅凭串口 `REFRESH` 完成或导出的 PNG 宣称没有残影。OTA 重启页是否完整呈现，也应与正常升级成功分别验收。

初始 bring-up 中 SD 挂载返回 `0x107`，未完成卡读写、断电恢复与 24 小时趋势持久化验收。电池供电、充电行为、PWR 时序和整板功耗未做专项测量。

新的验证应固定源码与镜像摘要，同时记录操作序列、刷新模式和物理观察。帧缓冲导出只证明生成像素，不能代替屏幕照片或长期残影检查。
