# WS397 局部刷新定位 demo

四组测试共用当前微雪底层驱动，按步骤区分原始窗口寻址、帧差分、旋转和设置页绘制。
测试不会保存设置。每次切换测试都先全刷建立黑白基准；每一步由用户手动触发。

## 启动与操作

在仓库根目录运行，将 `<PORT>` 替换为已确认的 3.97 英寸墨水屏串口。

```powershell
python tools/ws397/capture.py --port <PORT> --command t --seconds 120 --output .test-artifacts/ws397/t.log
```

程序会在 120 秒内收集串口日志。屏幕完成全刷后可直接用拨轮测试；收集结束不会退出 demo。
`--command u`、`v`、`w` 可分别启动其他组。一次只发送一个动作，等待刷新完成再操作。

| 动作 | 串口 | 实物按键 |
| --- | --- | --- |
| 固定原生窗口 | `t` | BOOT 依次切换 T/U/V/W |
| 自动差分窗口 | `u` | 同上 |
| 旋转差分窗口 | `v` | 同上 |
| 真实设置页 | `w` | 同上 |
| 下一步 | `n` | 拨轮向下或短按 |
| 当前帧全刷对照 | `f` | 拨轮向上 |
| 清回初始基准 | `b` | 串口命令 |
| 下一方向，重新建立基准 | `o`，仅 V/W | 串口命令 |
| 返回正常界面 | `r` | 拨轮长按 |

物理按键映射仅在局刷 demo 中生效。显示忙时会记录 `DEMO busy` 并拒绝该动作，
等待完成后重新操作。正常的“20 次局刷后全刷”策略仍然生效，日志会显示 `mono full`；
判断某一步是否为局刷时，以日志为准。配对确认或 OTA 会中断 demo。

## T：固定窗口与已知原始位图

屏幕显示五个编号外框，位置刻意不对称。第一步只在 1 号框内画黑色 L 和右下角黑点，
第二步把框内擦白，随后依次测试 2–5 号框。外框、标题和其他区域应该始终稳定。
L 的横边在上、竖边在左，右下角只有小黑点，可以观察上下翻转和行错位。

每个窗口固定为 64×32 像素。局刷直接发送独立生成的 256 字节单色图案，
绕过 UI 坐标变换、自动差分窗口选择和 framebuffer 裁剪。
全刷基准则由原生坐标写入 2-bit framebuffer，用于独立对照。

第一步日志应包含：`x=32 y=112 w=64 h=32 bytes=256`。

如果 T 已错位，问题范围落在底层窗口寻址、扫描方向或控制器状态；无需先排查设置页布局。
若位置正确但反复黑白切换出现残影，应继续检查旧帧 RAM、波形和基准保持。

## U：相同图案经过自动差分

使用与 T 相同的外框、图案、动作顺序和原生方向，但通过 UI 的 `pixel/rect` 绘制，
再经过当前帧比较、包围矩形计算和区域打包。标题不同，其余测试区域应与 T 一致。

若 T 正常而 U 异常，优先检查 framebuffer 绘制、差分边界和裁剪。
同一步的 T/U 窗口日志应一致，第一步都应为 `(32,112,64,32)`。

## V：四方向旋转

使用 U 的绘制和差分路径。先在方向 0 操作，再发送 `o` 依次测试方向 1、2、3。
每次换方向都全刷清回空框基准，再用 `n` 填入和擦除图案。
预期每一步只改变编号框内的内容，图案与该方向的标签保持一致。
IMU 的实时朝向不参与 demo 的方向选择。

如果 U 正常，只有 V 的特定方向异常，优先核对逻辑坐标转原生坐标和旋转后的差分窗口。

## W：真实设置页

直接调用设置页绘制函数，使用固定电量和连接状态，每四步切换到下一行；
组内步骤改变该行的选项。参数变化只存在于测试画面，不写入 NVS，
选择 ROTATION 行的选项也不会改变实际设备设置。用 `o` 单独控制测试方向。

如果几何图案正常而 W 异常，比较 `s` 导出的预期图像与实物：
预期图像本身就错位，排查 UI 绘制；预期图像正确、实物错误，排查局刷窗口或驱动。

## 同一帧对照与记录

发现异常后先拍照，记录测试字母、步骤和方向，再按 `f`（拨轮向上）。
`f` 直接全刷当前 framebuffer，不重新计算布局，也不推进步骤。

- 同一帧全刷后恢复：偏向局刷寻址、扫描或控制器状态问题。
- 同一帧全刷仍异常：结合预期 PNG 判断是绘制问题，还是全刷方向/驱动映射问题。
- 首次正常、连续切换才异常：重点检查基准与旧帧更新。
- 不同区域出现固定偏移、镜像或行循环：优先检查 RAM 窗口与地址指针。

导出软件预期图像：

```powershell
python tools/ws397/capture.py --port <PORT> --command s --seconds 20 --output .test-artifacts/ws397/expected.log
```

需要本机 Python 的 pyserial 和 Pillow。输出包含原始 `.bin` 和 800×480 的 `.png`。
PNG 使用原生屏幕坐标；竖屏测试时可旋转图片查看。
它表示固件准备显示的图像，不代表屏幕实际显示结果。

建议回报格式：`T，step=1，orientation=0：L 出现在框下方；f 后恢复`，
并附局刷前后照片及对应 `DEMO expected/window/done` 日志。

## 验证边界

构建只能验证代码与链接。窗口的实物位置、连续刷新残影、旋转方向和最终光学效果，
需要通过上述步骤在目标屏幕上确认。
